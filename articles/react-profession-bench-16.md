## 考察

GPTシリーズは着実に成長していますが、コンポーネント設計のスコアでClaudeに大きく差をつけられています。

生レポートによると、GPT-6 Astraも含めて、GPTシリーズはコンポーネント分割をほとんどしない傾向が見られます。その結果として数百行といった大きさの単一コンポーネントが生成されることが多く、これがコンポーネント設計のスコア低下につながっているようです。

React力が低いというよりはそういう癖なのかもしれません。おそらくプロンプトで矯正可能な範囲とは思われますが、このベンチマークではプロンプトで設計の指示をしないという設定です。デフォルトで良いコードを書けるかどうかが見られています。

それを差し引いても、以前の記事で述べたようにGPTシリーズはReactの新しいAPIの使用があまり見られません。今回`useSyncExternalStore`を使うようになったのは大きな進歩ですが、まだClaudeのほうが数歩先を行っている分野です。

評価者の記述もこれと一致している。005 の判定文から引くと——

## 4. モダン React API: `useSyncExternalStore` だけが動いた

| API | Sol high (39) | Sol max (39) | **Astra high (48)** | Fable 5.1 (43) | Opus 5 (41) |
|---|---:|---:|---:|---:|---:|
| `useTransition` | 0 | 0 | **0** | 0 | 0 |
| `useOptimistic` | 0 | 0 | **0** | 0 | 0 |
| `useActionState` | 0 | 0 | **0** | 3 | 3 |
| `useDeferredValue` | 3 | 3 | **3** | 3 | 3 |
| `useSyncExternalStore` | 0 | 0 | **7** | 6 | 8 |
| `useId` | 5 | 6 | **9** | 12 | 13 |
| `useMemo` | 26 | 25 | **17** | 25 | 28 |
| `useCallback` | 18 | 25 | **23** | 34 | 31 |

（アーカイブ数はリトライ分を含む。Astra は中断・再開が2度あったため 48。）

並行レンダリング系は **依然ゼロ**。第14回以降、これは全モデル共通の結論になってしまった。`useActionState` は GPT 系が 0 のまま——008 フォームアクションのスペックが `<form action>` を主題にしているにもかかわらず、である。

動いたのは `useSyncExternalStore` の **0 → 7** で、Claude 上位と同水準になった。005 ステータス監視の判定文を見ると、イベントバスの購読には正しく `useSyncExternalStore` を使い、ブラウザ API（online/offline、resize、matchMedia、visibilitychange）には `useEffect + addEventListener` に戻っている。**API を知っていて、使いどころを半分だけ当てている**という状態で、これが Effect 衛生 +0.29 の中身だろう。

もう一つ目を引くのは `useMemo` の **26 → 17** で、これは減っている。手動メモ化が減るのは React 19 的には健全な方向だが、パフォーマンス意識のスコアは動いていない（3.56 → 3.64）。評価者は「メモ化していない」ことと「メモ化すべき場所を判断していない」ことを区別しており、Astra は後者に読まれている。

## 6. 非コンパイル 1 件は、いつもの 008

s3 の 008 が `compiles: false`。s1・s2 では tsconfig の `noUnusedParameters` を緩めてコンパイルを通し、s3 では出荷時のまま残して落ちた。データモデルは3本とも未変更。**同じモデルが同じ罠に対して 2 回は逃げて 1 回は逃げなかった**、というだけの話で、コードの品質とは無関係——第15回 §6 で書いた「`compiles` 列が測っているのは設定を緩める意思」の、もっとも簡潔な実例になった。

## 8. 信頼性と運用

39 実装すべてが完走し、判定不能はゼロ。ただし運用面では今回が最も手のかかる回だった。

- **s3 の途中でランナーが 2.5 日間ハングした。** 使用制限の待機ループ中にホストがサスペンドし、復帰後もプロセスは生きたまま `epoll_wait` に留まり続けた。`run-samples.sh` は run.ts の*終了*を契機に再起動する設計なので、*ハング*には対応できない。手動で kill して `--resume` で再開した。
- その後もう一度ホストがスリープし、今度はプロセスごと落ちた。こちらは想定どおりのケースで、`--resume` で拾えた（書きかけの 008 は捨てて最初からやり直し）。
- Codex CLI は起動時に `token_expired` の 401 を吐きつつ別経路でリクエストを通していた。実害はなかったが、ログが騒がしい。

`run-samples.sh` にストール検知（一定時間ログもサンドボックスも動かなければ kill して再起動）を入れれば、一つ目のケースは無人で乗り切れる。

## 9. 注意書き

- 評価者は `sonnet-4.6` ピン、実装側は `-c model_reasoning_effort="high"` 明示（GPT-5.6 と同じ方式）。モデル ID `gpt-6-astra` は、架空 ID が 400 で弾かれることを対照として確認したうえで使った。
- v1 スキャフォールドの二重 React 欠陥（`docs/audit-2026-07-26.md` §5.1）と 008 のデータモデル欠陥（第15回 §6）は未修正。Astra も他条件と同じ環境を踏んでいる。
- `useMemo` の減少（§4）を「React 19 らしくなった」と読むのは早い。React Compiler が入っていない v1 スキャフォールドでは、メモ化しないことは単に最適化していないことでもある。v2（Compiler 有効）で同じ傾向が出れば、そのときに評価が変わる。
